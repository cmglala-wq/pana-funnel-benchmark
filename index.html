Definitions & data sources — Pana

  • Signups — user.createdAt, Pana Global (usertype = GLOBAL), signup-month cohort.
  • Wizard opened — first Amplitude event of type Bridge Onboarding Started or Viewed Onboarding Bridge Wizard, per user, from panaapp-16ce3.amplitude.EVENTS_396830. This is t1 in Pana's own canonical KYC event table — the true first step, ahead of anything Persona's backend tracks. Query diag-onboarding-wizard-started-monthly.
  • Persona application created — a personainquiry record exists for the user (BigQuery, planetscale_pana.personainquiry). This is t7 in the same canonical table — created by Pana's backend once the user has gone far enough into the wizard, not when they open it.
  • Approved — bankapplication.status = 'Approved'. Metabase queries funnel-3step and persona-funnel-flow (cross-checked, agree to within 0.3%).
  • Scope stops at approval. Funding/activation metrics are tracked separately and intentionally excluded here to keep this a pure onboarding/KYC read.
  • All figures pulled via BigQuery through the Metabase API, panaapp-16ce3.planetscale_pana and panaapp-16ce3.amplitude, Sep 8, 2026.
  • Correction, Sep 8 2026: the first version of this deck measured "Started KYC" from the Persona-application-created event (t7), because that was the earliest step the existing dashboard query (persona-funnel-flow) tracked. Claudia flagged that KYC should start counting from when Persona actually takes the user, which led to checking Pana's own canonical event table and finding the wizard-open event (t1) is the true start — 25pp earlier than what the deck first reported.

On the external benchmark figures

  • Compiled from secondary industry sources (fintech CX/CRO round-ups citing Signicat and neobank activation research), not one primary index — treat ranges as directional, not exact.
  • Definitions vary by source (e.g. "activation" sometimes means first transaction, sometimes 5+ transactions); ranges here were matched to Pana's stage definitions as closely as the source allowed.
  • No external source publishes a clean "signup → wizard opened" rate, so that stage is shown for internal diagnostic value only, with no scored verdict. Confirmed by a multi-pass check (own research plus independent cross-checks) against Sumsub, Alloy, Persona, Veriff, and Plaid — identity vendors define a technical "start" event (e.g. Veriff's started/7001, Plaid's IDENTITY_VERIFICATION_START_STEP), but their own funnels begin after a verification session is already created, not at account signup. That earlier handoff sits outside what any vendor or industry report measures, so it isn't a gap in this research — it's an industry-wide blind spot. It's exactly why "wizard opened → approved" is the right stage to benchmark against their "KYC completion" figures — it's Pana's closest match to what vendors mean by "started."
