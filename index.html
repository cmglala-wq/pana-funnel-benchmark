Definitions & data sources — Pana

  • Signups — user.createdAt, Pana Global (usertype = GLOBAL), signup-month cohort.
  • Started KYC / Approved — Persona (Bridge KYC) application events, cross-referenced against bankapplication. Metabase query persona-funnel-flow (Started KYC and Approved steps only — Funded/Active steps excluded from this pass by design).
  • Bank approved (volume chart) — bankapplication.status = 'Approved'. Metabase query funnel-3step.
  • Scope stops at approval. Funding/activation metrics are tracked separately and intentionally excluded here to keep this a pure onboarding/KYC read.
  • All figures pulled via BigQuery through the Metabase API, panaapp-16ce3.planetscale_pana, Sep 8, 2026.

On the external benchmark figures

  • Compiled from secondary industry sources (fintech CX/CRO round-ups citing Signicat and neobank activation research), not one primary index — treat ranges as directional, not exact.
  • Definitions vary by source (e.g. "activation" sometimes means first transaction, sometimes 5+ transactions); ranges here were matched to Pana's stage definitions as closely as the source allowed.
  • No external source publishes a clean "signup → started KYC" rate, so that stage is shown for internal diagnostic value only, with no scored verdict. Confirmed by a multi-pass check (own research plus independent cross-checks) against Sumsub, Alloy, Persona, Veriff, and Plaid — identity vendors define a technical "start" event (e.g. Veriff's started/7001, Plaid's IDENTITY_VERIFICATION_START_STEP), but their own funnels begin after a verification session is already created, not at account signup. That earlier handoff sits outside what any vendor or industry report measures, so it isn't a gap in this research — it's an industry-wide blind spot.
